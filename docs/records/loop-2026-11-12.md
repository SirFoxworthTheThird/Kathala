# Closing the loop again: the marked revision in the editor's hands

**Plan:** `round-trip-plan-2.md`, T5.4, *Close the loop again*.
**Build:** 79371d8, which is T7 and all of T5. It was merged as #667 while the run was going, with the same content.
It was served frozen at `http://localhost:4192/`.
**Reports:**
- `writer-run-2026-11-10-loop2.md`, with the finished world in `writer-run-2026-11-10-loop2.pwk`;
- `editor-run-2026-11-10-loop2.md`.

## How it was run

The same two agents and the same prompts as the first loop (`loop-2026-11-10.md`), with a new book and one round
more.
- **The writer** chose the pen name Elin Ashgrove. *The Salt Ledger* is 6 chapters and 16 scenes: 12,374 words as
  first sent, 13,756 at the end.
- **The editor** was Ines Marlowe, working in LibreOffice with tracking on.
- **The rounds.**
  1. The writer wrote the book and sent it.
  2. The editor edited it and wrote a letter.
  3. The writer brought that in, revised, and sent the book back.
  4. The editor received that revision and edited again.
  5. The writer brought that in, revised, and sent it a third time.
  6. The editor made a last pass.
  7. The writer brought that in and finished.
- **What the prompts did not say.** Neither agent was told that a marked file exists.
  - The writer was asked to send the book *the way the guide says* and to note what the export dialog offered. It
    offered the marked file, ticked, and the writer kept it, both times.
  - The editor was asked to check the writer's account *the way you normally would*, and to say honestly if a script
    was needed.
- **Blindness.** As before: neither agent read `docs/records/` before its report was written. The writer opened
  `ux-review.md` at the very end.
- **Interruptions.** Usage limits stopped an agent five times, and the machine was restarted more than once.
  - The editor was stopped twice in round 2 and once after round 3's handback, before the report.
  - The writer was stopped once in round 3, and once after round 4, when the report and the `.pwk` were already
    written. Only the writer's closing message was lost.
  - Each agent was resumed where it stopped. Both checked their state first, and nothing was redone.
  - The session's model was changed after the editor's second stop. From there on both agents ran on the new one.
  - The server was restarted four times, each time from the same frozen build.

## The plan's three expectations

| Expected | What happened |
|---|---|
| The editor checks the writer's account without a script | **No.** The editor needed a scripted comparison in both rounds. |
| Every reply arrives under its comment | **Yes**, both ways, in every round. |
| The file the editor sends back brings in no change twice | **Yes.** Nothing came in twice, in either marked round. |

**Why the editor needed a script.** The marked file held the right text, and the editor's own comparison proved it:
- with every change rejected it was the editor's last file, the cover's word count and an empty paragraph or two
  aside;
- with every change accepted it was the writer's revision.

But the editor could not *read* it where the writer had rewritten:
- one paragraph carried 113 alternating one-word marks in round 2, and another 95 in round 3;
- the old paragraph then appeared again, whole, as an insertion.

In round 3 the writer sent a clean copy as well, because the editor asked for one. The editor read that, and still ran
the comparison to be sure of it: *an hour's work instead of an afternoon's*.

## New findings, for the next part

Ranked by what they cost. *Confirmed here* means it was checked against the code or the files after the run.

### The marked file

1. **Rewriting is marked word by word, and the old paragraph comes back as new.** The writer's F1 and the editor's
   E-1. It is the costliest finding of the run.
   - **Confirmed here.** `markedParagraphs` pairs the paragraphs between two unchanged ones in order, and compares
     each pair word by word. It never asks whether the two resemble each other.
   - A small case shows it. Two new paragraphs go in before one that gained a word:
     - the first new paragraph is compared with the old one, and comes out as eight struck-and-inserted pairs;
     - the old paragraph, barely changed, is then inserted whole.
   - **The dialog's count follows the marks.** It said *160 changes*, then *134*. The writer counted about 82 and
     52, and the editor about 30 real changes in the first. `markedPlan` counts each stretch put in or taken out.
   - **The editor's first two wishes** answer it: mark a whole new paragraph as one insertion, and mark a
     rewritten sentence at the level of the phrase or the sentence.
2. **A declined edit and the writer's new writing look the same.** The editor's E-2.
   - This is D-4 as taken: the file is measured from the editor's text, so an edit turned back is the writer's
     change.
   - It mattered once. The writer turned back one sentence and left it off the list in the cover note. From the
     file, the editor could not tell a choice from an accident of the marking.
3. **A thread at a scene's start is not read back after LibreOffice saves the file.** Found here, by the counts.
   - Round 2's file held 84 comments and the import's plan saw 77. Round 3's held 102, and the plan saw 86.
   - The difference is the threads the export had put at the start of their scene, *On words since rewritten*, with
     the replies under them: 5 threads, then 10.
   - **Confirmed here.** LibreOffice saves a comment on no words as a bare reference, without its range marks.
     `docxRead` places a comment by its range marks only, so such a comment is never read.
   - **Nothing was lost in this run:** the notes were already in the book, and the editor answered none of those
     threads. Had the editor replied to one, or resolved it, that would not have come in, and nothing would have
     said so.
   - Not tested: whether a comment an editor makes in LibreOffice with nothing selected is saved the same way. If
     so, it would not come in either.
4. **Rejecting every change does not quite give back the editor's text.** The editor's E-6.
   - **Confirmed here in the round-2 file.** Eight wholly new paragraphs have an untracked paragraph mark, with the
     mark before them tracked. That is Word's form, which T5.1 chose on purpose.
   - LibreOffice's reject-all left an empty paragraph for two of the eight. Both follow a paragraph with no change
     of its own. That looks like the pattern, and it is not isolated yet.
   - T5.1's probe tested the app's own reader after a LibreOffice save. It did not test LibreOffice's reject-all.
   - The cover's word count also changes without a mark.
5. **A comment on a heading does not go back.** The editor's E-3. The app lists a heading's comment apart, with
   Dismiss, and the marked export sends only the notes. The editor sent 39 comments and got 38 back.
6. **The app's words under the editor's name.** The editor's E-4. A thread whose words were rewritten goes back
   beginning *On words since rewritten: "…"*, inside a comment signed by the editor. There were five, then ten.
   The line was never doubled.
7. **Every comment's date is the export's.** The writer's F5 and the editor's E-5.
   - **Confirmed here:** `compileDocx` writes the export's time on every comment.
   - A round-1 comment carried three dates by the end. Neither side can tell which pass a comment belongs to.
8. **The file does not open with tracking on.** The editor's E-7. The export writes no `settings.xml`. The editor
   turned tracking on by hand each time, and made no untracked edit.
9. **No clean copy beside the marked one.** The editor asked for one, and the writer made it with a second export,
   *For an editor* unticked.

### Bringing the file in

10. **The editor's replies, and a thread resolved, arrive unannounced.** The writer's F3.
    - *Edits brought in* speaks of changes and new comments only.
    - Six of seven replies sat in resolved threads, which Notes hides by default, with no mark of a new reply.
    - The writer found them because the editor's email said to look.
11. **A change the writer then made by hand waits for ever.** The writer's F6. Refused once, it stayed in the
    list after the writer had typed the editor's words in, and only Reject cleared it. The list gave no warning
    beforehand that the words had changed.
12. **The letter's headings and a long sign-off become tasks.** The writer's F4, seen in three letters.
    - A section heading, *WHAT MOST NEEDS WORK*, was ticked as a point under the heading before it.
    - A sign-off with a clause after it was ticked. A table was flattened into one point.
    - The first letter took 19 clicks and a delete to put right.
13. **A note loses its place when a few words go into its passage.** From the writer's round 2: five words
    inserted in the middle of a note's words sent its thread to the start of its scene in the marked file, as on
    words since rewritten. T7.2 stopped a note jumping to a near match, and this is that rule's cost.

### Writing

14. **One Enter on the Page looks like a paragraph and is not one.** The writer's F2, reproduced twice.
    - A scene typed with one Enter between paragraphs showed as paragraphs on the Page.
    - Read ran it together into one block.
    - The Word file held one paragraph with eleven line breaks.
    - **Confirmed here:** `paragraphBlocks` splits on blank lines only, and `compileDocx` writes each remaining
      line end as `<w:br/>`.
    - The guide says a single Enter is not a paragraph, and also that *the book and every export read your prose
      the same way*. Read and Word do not.
    - It cost the writer a scene, and it was found by luck, before sending.
15. **Smaller, from the writer:**
    - the Page suggests for a scene's header someone who is only quoted there;
    - Export, Drafts and Bring in edits are not offered on Cards;
    - the end of a scene is hard to reach on the Page.

### Not the app's

- **The editor's tools.** LibreOffice's scripting cost the editor more than the file did. They are T-1 to T-8 in the
  editor's report:
  - a reply made through its API is saved as a top-level comment;
  - a comment made with tracking on is itself a tracked change;
  - a comment cannot be anchored to some ranges.
- **Suspected only:**
  - LibreOffice's save turns automatic hyphenation on in the file's settings, which may reach Word. Not tested.
  - The file still says *marked by Elin Ashgrove* after the editor has accepted every one of the writer's changes.
    That is harmless: the import then finds none of the writer's marks, and reads the file as any other.

## What worked

- **Bringing a file in was exact, three times running.** In all it was 83 changes, 59 comments and 9 replies,
  none in the wrong scene, none dropped and none twice. Two of the three files came from a marked file, renamed
  and saved by LibreOffice.
- **The threads.** Each reply was under its comment in both directions, and resolved was carried both ways.
- **The writer's changes never came back as changes.** The editor accepted them in the file, and the app offered
  none of them again.
- **The offer.** The writer found the marked export without being told of it, and understood what it would send.
- **The book survived everything:** five stops and the restarts between them, with nothing redone.

## What this asks of the next part

The marked file carries the right text and the right threads. It is not yet something an editor can read. In the
order the run ranks them:

1. **Make the marks readable** (findings 1 and 4):
   - pair a changed paragraph with the one it resembles, and mark a new paragraph as one insertion;
   - count changes as a reader would;
   - make reject-all give back the editor's text in LibreOffice too.
2. **Lose nothing of a thread** (findings 3, 5, 6, 7 and 10):
   - read a comment that has no range;
   - send a heading's comment back;
   - keep each comment's date, and the app's words out from under the editor's name;
   - say when replies have come in.
3. **Say which changes turn an edit back** (finding 2), in the mark or in the margin, and offer the clean copy
   (finding 9).
4. **The single Enter** (finding 14) is the writer's costliest finding outside the round trip, and is not T5's.
