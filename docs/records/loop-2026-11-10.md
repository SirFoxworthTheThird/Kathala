The same two agents, with the same prompts as the first run (`writer-run-2026-11-09-blind-editor.md`), and a new

- **The rounds.** The writer sent the book. The editor edited it and wrote a letter. The writer brought the edit in,

- **Blindness.** Neither agent read `docs/records/` before the end, and the prompts named nothing being measured.
  Both report that the repository's `CLAUDE.md` was put into their context at the start. It describes the data

  export. The server was restarted from the same frozen build, and nothing was redone.

## The plan's three expectations

| | Expected | Round 1 | Round 2 |

**How they were measured.**
- **Tracking off.** The app deletes a change once it is decided, so it cannot be read back from the store. The
  import's own plan (`planImport`) was run instead on the editor's two files. Each was run against the draft it
  names, taken from the `.pwk`. It found 0 edits made with tracking off in each round, and 59 + 1 move and 21
  tracked.
- **The writer's own counts** agree: *60 changes in 13 scenes* and *21 changes in 10 scenes*, every one in the scene
  it was made in.
- **The greeting.** It is the writer's own observation, in `notes-round2.md`: *the greeting and sign-off were
  unticked for me*.

**The count against the editor's, one apart in each round, for one reason.** The app counts the file's runs of
tracked changes (T1.3). An editor counts what they meant.
- **Round 1.**
  - The editor's list has 61 entries.
  - Two of them are one move, and the app shows it as one change.
  - Two others are one rewrite in two halves, his own *(second half of the same rewrite)*. They keep a word between
    them, so the file holds two runs and the app shows two.
  - As he meant them, that is 59. As the file has them, 60.
- **Round 2.**
  - Edit 17 deletes a paragraph, and edit 18 deletes the first words of the next.
  - Nothing unchanged lies between them, so the file holds one run, and the app shows one: the writer's *two-paragraph
    cut*, which she accepted whole.
- **So the expectation as the plan wrote it was too strict.** No reading of the file alone gives the editor's
  count. What the app can match is the file, and it does, exactly, in both rounds. The first run's gap was 85 or 81
  against 66.

## New findings, for the next part

From the writer's report, ranked as it ranks them, with what was confirmed here:

1. **R2-1, high: an Accept applied to a different sentence.** The writer had rewritten the sentence a change was
   on. Accepting it found another *looked at* in the scene and replaced that one, giving *she raised his eyes to
   him*, with no message.
   - **Confirmed in the code:** `applyHunk` places a change through `placeNote`, which treats surroundings that do not
     match as a cost, never as a reason to refuse. A short change finds any exact match.
   - A change that has nowhere near its own words should be refused, as three were.
2. **N1, medium-high: a header line being typed is lost** when a chapter retitle saves (reproduced 3 of 3). This is
   T4's open suspicion S4 in another form, and now reproduced.
3. **R2-3, medium: a note jumped chapters.** A note whose words were rewritten moved to another chapter, onto a
   near-match (the same matcher, with no minimum).
4. **R2-2, medium: Undo reached past an Accept.** Undo straight after an Accept undid an older Find & replace in
   another chapter. Accepts are not on Undo.
5. **N2, medium: typing before a header's `[`** turns the header into prose.
6. **R2-4, low-medium: "ch.3" with no space** after the dot gets no chapter link from a letter's task (7 of 7).
7. **R3-1, low-medium: a comment on an unchanged chapter heading never reaches the app.** It is counted under
   *matched no scene*, which is not where it was.
   - **Confirmed in the code:** `useEditImport` stores a heading or title-page line only where its text changed.
   - T1.4's record says comments there are counted, not brought in. Its first line, though, says `outsideScenes`
     lists a line with a comment, which reads as if they are shown. Both agents put a comment on a heading to
     test it.
8. **R2-5, low: drafts with one name.** Two exports in the same minute made two drafts named alike. T2.3 names a sent
   draft to the minute, and nothing keeps two in one minute apart.
